# 0.3.1 — Zalesak FCT for sharp, conservative color tracers

status: CPU and WGSL implementation complete; 10k-step CPU conformance and null-backend pipeline validation pass; browser parity/performance pending
depends on: 0.3.0
milestone: draft.txt milestone 1 quality bar

## 1. goal

donor-cell upwind is monotone and conservative but diffuses dye fronts. Add a
Zalesak flux-corrected transport step for the three dye tracers. It must preserve
the shared-face conservation rule and keep each tracer within local bounds of the
low-order solution. Mass and energy remain donor-cell in this first version: mass
anti-diffusion would change compaction and the pressure solve, while energy needs
its own thermal/phase validation.

## 2. scheme

### 2.1 low-order state

The stored face volume flux F is computed once and outflow-limited by section 5.1.
Donor-cell advects m, dr, dg, db, and E with this same F. The low-order dye result
q_L is monotone and nonnegative when the per-cell volume outflow is <= 1.

FCT applies only to dr, dg, and db as conserved tracer densities (not q/m ratios).
The first version bounds density extrema; ratio-aware limiting is deferred until it
can be coupled to mass corrections without changing the pressure/compaction path.

### 2.2 anti-diffusive face flux

For a face oriented from left/bottom cell L to right/top cell R, use the stored
signed volume flux F and source tracer values q_src,L, q_src,R:

	A_low(F) = F * (F > 0 ? q_src,L : q_src,R)
	A_high(F) = F * (q_src,L + q_src,R)/2 - F*F * (q_src,R - q_src,L)/2
	d(F) = A_high - A_low = 0.5 * abs(F) * (1 - abs(F)) * (q_src,R - q_src,L)

The implementation uses the final expression. It is valid for |F| <= 1; compute_flux
already clamps each stored face to that range. FCT is an additive scalar correction,
not a volume flux. The section 5.1 outflow budget applies to F only; adding d to F
or counting d in k_out is dimensionally incorrect. The Zalesak bounds below limit d.

### 2.3 Zalesak limiter

For each interior cell and each dye, use the 3x3 neighborhood of q_L for q_min and
q_max. With the four signed corrections dW, dE, dS, dN (positive in +x/+y face
orientation), the cell's correction increments are +dW, -dE, +dS, -dN.

	P_plus  = sum(max(increment_face, 0))
	P_minus = sum(max(-increment_face, 0))
	Q_plus  = q_max - q_L
	Q_minus = q_L - q_min
	R_plus  = min(1, Q_plus / P_plus)   (1 when P_plus is 0)
	R_minus = min(1, Q_minus / P_minus) (1 when P_minus is 0)

For each face, both adjacent cells recompute the same d from the same source values
and stored F. If d > 0, alpha=min(R_minus(L),R_plus(R)); otherwise
alpha=min(R_plus(L),R_minus(R)). Apply alpha*d with opposite signs to the two cells.
This keeps the correction conservative. A small limiter safety margin absorbs f32
rounding at a zero/min/max bound; it does not clip field values or alter mass.

The low-order update and FCT correction are separate ping-pong results. The GPU
keeps a third mass texture as the FCT output, plus limiter factors for the three
dyes; temperature/energy remains on its existing ping-pong path.

## 3. configuration and interaction

	fctLimiter: 0 = upwind only, 1 = dye FCT (default on)
	f key toggles the limiter live

## 4. validation

- conservation: closed-box drift is limited by f32 field stores. Record the measured
  floor; use 1e-6 relative as the acceptance ceiling for 10,000 steps with FCT.
- sharpness: in a 2D constant-velocity dye-front test, measure the cells between 5%
  and 95% of the initial dye jump after 240 steps at N=256. FCT width must be no more
  than one third of the upwind width.
- monotonicity: zero negative dye cells; no local dye value outside its 3x3 low-order
  bounds beyond f32 rounding; no change to mass overpack or divergence versus the
  upwind-only path at the same parameters.
- emitter and paint accounting remains below 1e-6 drift.
- GPU parity against the CPU reference below 2e-6 relative after 500 transport steps.
- browser GPU cost at N=512 and N=1024 is measured before claiming a speedup or
  accepting the <30% overhead target; no timestamp-query feature is required.

## 5. implementation notes

- Keep source and low-order fields immutable through limiter_prepare/apply. The GPU
  FCT output must not alias either input; otherwise neighboring invocations race.
- Use the same face orientation and operation order in CPU and WGSL.
- Never clip negative values after the fact; reduce the face correction by the
  Zalesak ratios instead.
- The low-order outflow limiter protects donor-cell positivity. Do not fold scalar
  anti-flux into the volume flux limiter; FCT's local bounds protect the corrected
  tracer update.
- The original design proposed applying FCT to m, dye, and E and combining its
  anti-flux with k_out. That combination is invalid: d has tracer-density units and
  is not an independent volume flux. Restrict this first implementation to dyes.
