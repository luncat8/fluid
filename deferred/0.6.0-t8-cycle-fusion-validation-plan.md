# Deferred: repeat auto-policy fusion A/B for cycle

status: deferred; not on the current 0.6.0 work path

## Why deferred

The t8 fusion implementation is numerically bit-exact against its unfused WGSL
passes, but device measurements do not support enabling it by default. Fixed
schedule means are below the >3% frame-time adoption gate in all four scenarios.
One auto cycle pair clears the gate (3.79%), but it is a single unreplicated
comparison; the other auto scenarios do not clear it. Repeating this now has low
expected value relative to the remaining 0.6.0 work.

Keep `cfg.fusePasses = 0`. Do not schedule another fusion capture unless fusion
becomes a higher-priority optimization or a reproducible cycle-specific issue is
reported. The evidence and full caveats are in
`archive/0.6.0-mac-captures-t8-worklog.md`, section 6.

## If reopened

Use the same build, device, N=512, K=20, FCT, cycle count, and four auto scenarios
for both modes. Add an explicit pipeline/device warm-up and exclude those frames
from measurement. Interleave several `fuse=0` / `fuse=1` pairs (rather than
running all captures of one setting first), record full-run frame-time savings
and non-timing diagnostics, and keep the default at 0 unless replicated pairs
clear the >3% frame-time gate without state or diagnostic regressions.

The browser currently has no warm-up/discard window; implement that only as part
of a deliberate re-open, not as a standalone change.
