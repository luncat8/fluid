# 0.7.0 t8b — keyboard-only input binding

date: 2026-10-24
plan: 0.7.0-plan.md t8b
status: implemented and validated headlessly

## review

The existing `attachInput(element)` deliberately owns pointer painting and keyboard
shortcuts together. A game embedding Fluid may own pointer gestures itself, so the planned
`bindKeys(element)` entry point should not install any pointer listeners or disturb an
existing pointer owner. Key bindings must remain detachable independently and view keys
must continue through the engine's single view-mode writer.

## implementation

- `src/app/input.js` now tracks pointer and key listeners separately. The existing
  `create()` path still installs both, while `createKeys()` installs keys on the supplied
  target and has no canvas dependency.
- `src/api/engine.js` exposes `bindKeys(element)` and `detachKeys()`. Rebinding replaces
  only the prior key owner; binding keys alongside `attachInput()` removes/replaces the
  old key handlers while preserving pointer handlers. `detachInput()` still tears down all
  input, including a separately bound key target.
- README and the 0.7.0 task list describe the independent lifecycle.
