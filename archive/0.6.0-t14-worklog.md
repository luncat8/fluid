# 0.6.0 t14 — projection quality gate and memory priority

## Decision

Memory is an allocation estimate, not a product limit. The 200 MB line is removed from the acceptance gate. A texture-format change is only interesting when it improves measured speed while preserving conservation, true Poisson residual, divergence, and believable behavior; memory reduction alone is not a reason to adopt it.

The CPU third-level multigrid candidate did not clear the same-state quality gate, so it was not ported to WGSL and no GPU timing was spent on it. The shipping two-level K20 solver remains unchanged.

## CPU oracle trial

`experiments/mg-three-level.js` adds an opt-in three-level CPU experiment behind `mgOracleLevels`; default configurations still use the shipping two-level solver. `run_mg_three_level.py` is the one-command runner. Each candidate warms under two-level K60, then measures one step from the same warm-state construction with two-level K20 as its comparison row.

At N=128, dt=1/240:

- Dam, 180 warmup steps: two-level K20 true residual `7.744e-2`, post-projection divergence ratio `4.305e-4`. Three-level variants had similar true residuals (+1.9–2.1%) but divergence ratios `3.667e-3` to `4.006e-3`—about 8.5–9.3x worse.
- Cycle, 120 warmup steps: two-level K20 true residual `3.384e-2`; three-level variants regressed it by 15.6–24.1%. The reported post-projection divergence ratio was unchanged for this sample.
- Increasing the top solve from K20 to K40 did not recover quality. CPU wall time is recorded for completeness but is not GPU performance evidence.

These are sufficient to reject the tested configurations. The complete output is in `experiments/logs/2026-10-21-mg-three-level.log`.

## Diagnostics and validation

- Browser captures now retain the sampled peak's frame number, absolute Poisson residual, and RHS alongside the normalized residual, to localize boiling-flow spikes.
- `run_gpu_cycle_residual.py` launches a fixed N=512, 600-frame, cycle-only K20/two-cycle capture with `dt=1/240` (`ns=4`).
- Browser report and sampled-peak tests pass; `node experiments/run-all.js --quick` passes all 12 suites; allocation accounting passes at N=256/512/1024. Python wrappers compile and the CPU wrapper was exercised.
- The real-device cycle capture remains necessary to identify the hardware peak frame and compare the reported absolute residual/RHS; CPU oracle data cannot substitute for it.
