Decision: **reject `t17`** (no WGSL port, matching `t14`). Confinement was compensating first-order SL numerical viscosity; stacked on MacCormack, `eps >= 1` worsens `errL2`, `eps >= 0.5` creates new velocity extrema (`> 80`), and even `eps=0.25` spins core vorticity to `1.81x` initial with `3.3x` higher divergence for `-0.023` `errL2` (vs `-0.189` from `sl -> mac`).

## 3. `t8` pass fusion implementation (`cfg.fusePasses`)

Audited the 0.5.0+ compute graph against WebGPU core limits (`requiredLimits: {}` -> `maxStorageTexturesPerShaderStage = 4`, no `read_write` on `rgba32float`) and `AGENTS.md` flat-code rules:
- `advectScalar` (`src/gpu/shaders.js`, `src/gpu/passes.js`): fuses `advectMass` + `advectTherm` (`trans` group `5 -> 4` dispatches, 3 sampled textures + 2 write-only `rgba32float` storage textures), sharing `fluxTex` loads and donor-cell weights via flat `donorUpwind` helper.
- `phaseSources` (`src/gpu/shaders.js`, `src/gpu/passes.js`): specializes `shaders.phaseEos` with `override APPLY_SOURCES: u32 = 0u` (`pipes.phaseEos` = `0`, `pipes.phaseSources` = `1`) over an explicit `phaseLayout` (`createBindGroupLayout`, matching `projLayout` so both pipelines validly share `groups.phaseB` on real WebGPU). Folds `heatSources` into the second `phaseEos` (`phase` group `6 -> 5` dispatches, eliminating an 8.4 MB `therm` read+write per substep at `N=512` and duplicate `evalPhase`; `therm` flips `4x`/substep instead of `5x`, tracked in `state.t`).
- Kept `cfg.fusePasses = 0` by default until device A/B rows clear the `> 3 %` frame-time bar in `0.6.0-plan.md` §4.3.
- Wired `&fuse=0|1` and `fuse=` header output in `experiments/browser-tests.html`, updated `experiments/gpu-log-table.js` (`mac`, `fuse`, `vel`, `trans`, `phase`, `endTrue`), and added presets + one-click wrappers (`run_gpu_mac_k20.py`, `run_gpu_fuse_fixed_k20.py`, `run_gpu_fuse_k20.py`, `run_gpu_mac_fuse_k20.py`).
- Also replaced `.r/.g/.b/.a` LHS component writes in `heatSources` with `vec4<f32>(...)` value construction after catching that `wgsl_reflect`'s `WgslExec` interpreter drops `.r/.g/.b/.a` swizzle writes on `var vec4<f32>`.

Only auto `cycle` clears 3%, on a single pair. This does not establish a

Quality is unchanged in the captures: after excluding throughput/timing and the
`fuse` header, all state and diagnostic lines match exactly for `06_38` vs
`06_40`, `06_38 tests1` vs `06_41`, and `06_42` vs `06_43`. Every scenario is
`OK`. Auto jet has the same small energy drift warning in both modes
(`1.216e-6`); it is not a fusion regression.

Measurement caveat: `browser-tests.html` reports `frames/s` over all 600 frames;
it has no explicit warm-up/discard window. Its GPU timing line aggregates sparse
query results read at stats polls (20/21 samples in these runs), not only the last
60 frames. The blobs profile averages vary sharply between captures (`step sum`
1.503 vs 2.351 ms for fused and 1.534 vs 3.161 ms for unfused), but the log does
not emit per-sample timings to locate the cause or attribute it to a clock state.
Use `frames/s` for full-run throughput; do not call the profile line a last-window
measurement.

Decision: close the t8 evaluation without adoption. Keep `cfg.fusePasses = 0`;
the fixed means are below the bar and the lone auto cycle win is not replicated.
The implementation remains available behind the flag. If cycle-specific fusion
is worth pursuing later, add an explicit warm-up/discard period and interleave
multiple auto A/B runs before reconsidering the default.
