## why

The device split is confirmed, so the old "1 cycle is residual-neutral in jet and
cycle" sentence can be checked on the residual that counts. That sentence came
from `residualNorm()` after `step()` on one step inherited from a 2-cycle warmup.

## result

`node experiments/mg-cycle-gate.js`, dt=1/240, N=128, K20, pre4/post8.

Same-state, one step after 180 steps at K60:

- dam solve 18.1x, drift 1.05x. The old column hid the regression; divAfter did not.
- blobs solve 18.9x, drift 1.11x. Same.
- jet solve 1.03x, rel 1.00x.
- cycle solve 1.00x. This is the inherited-pressure row, and it is not the decision.

Own trajectory, 90 warmup + 90 measured:

- jet peakSolve 1.00x, peakDivA 1.00x, over=0.
- cycle peakSolve 27.4x (0.037 -> 1.02), peakDivA 36.9x (17 -> 626).

1 cycle stays rejected for dam, blobs, and cycle. Jet is the only neutral row.
Not adopted: the hardware `true` pair does not exist yet. The fixed-ns jet rows
from 04_23 already match on maxVel (109.5 vs 109.6), over=0, and maxDiv
(23.7 vs 27.9), with +54 % fps, but their poissonTrue is the drift column.

## device pair

`2026-10-21-08_02` is 2 cycles, `...1` is 1 cycle. Same machine, N=512, ns=4,
K20, 600 frames, new true column.

- settled true 0.01145 -> 0.01000. drift 0.01229 -> 0.01057.
- frame-1 true 0.0671 -> 0.1238, and drift equals true on both. cold start only.
- maxDiv 27.87 -> 23.70, end 22.29 -> 21.18. maxVel 109.62 -> 109.54. over=0.
- pressure span 4458 -> 4369. the mean moved; the gradient did not.
- conservation ok on both. phases within a few thousand cells of 262144.
- fps 104.8 -> 157.6. press 1.219 -> 0.641 ms/substep.

Adopted for jet only. The frame-1 gap is a first solve, not a persistent
regression, and the settled residual is the number the plan ranks. Dam, blobs
and cycle stay at 2. The gate is `productCycleGate` so a re-run of the oracle
scripts still uses the cycle count those logs named. `&cycles=` pins an A/B.
