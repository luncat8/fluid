## review of the previous task (0.7.2)

0.7.2 (one readback staging buffer, one map per frame) is sound structurally, and closing it
surfaced one real defect, fixed here first:

- a readback that landed after a reset or a resize was not dropped on the stats and probe
  legs. `pollMap` compared `pendingGeneration`/`probeGeneration` — both captured *before* the
  reset — against the generation also captured before the reset, so the compare was
  ineffective and a stale snapshot could be ingested into the freshly rebuilt field. the
  buoy and phase legs were re-based rather than compared, so they were the only safe ones.
  the fix is the smallest rule that covers all four channels: after `mapAsync` resolves,
  compare the generation captured at poll start against the *current* `statsGeneration`; a
  reset, resize or load bumps it, so the whole snapshot is dropped as one. the four
  per-channel generation counters (`pendingGeneration`, `buoyGeneration`, `probeGeneration`,
  `phaseGeneration`) collapse into that single check; the `buoyFrame`/`probeFrame`/
  `phaseFrame` stamps stay, because they carry ingest frame numbers, not staleness.
  new mock regression test "a reset while a map is in flight drops the whole readback"
  (`statsFrame` stays 0, buoy samples stay 0); verified it fails when the guard is disabled.

the suggested "two-deep readback ring" (write B while A is mapped) stays unchosen on
purpose: one map per frame already costs less than the alternative's two in-flight maps and
an extra buffer, and the skip-a-frame staleness it would remove is already handled by the
generation drop above. it remains a listed candidate, not a scheduled one.

## implementation

the dam float now reports the momentum of the fluid inside its footprint — never applies it:

- `src/core/buoy.js`: `SAMPLE_LEN` 6 → 8 (`S_MOMX=6`, `S_MOMY=7`, raw `Σ m·u` / `Σ m·v`,
  same convention as every other slot). `ingest(fresh, frame)` takes an optional frame stamp;
  without one the sums are refreshed but the dP/dt estimate is left alone. `state` gains
  `momX`, `momY` (raw sums), `uMass`, `vMass` (mass-weighted mean velocity — distinct from
  the count-weighted `ux`,`uy`, which dye-free spray cells drag toward zero) and `forceX`,
  `forceY`. the derivative lives in the closure (`prevMomX`, `prevMomY`, `prevFrame`), not in
  the capture: `F = Δ(Σ m·u) / ((f₂−f₁)·frameDt)` between consecutive framed ingests, and the
  first framed ingest after a reset or after `syncDerived()` reports force 0, never a spike
  against construction-time zeros. `syncDerived()` recomputes the derived fields from the
  current sample and re-anchors the baseline — the save/restore path calls it.
- `src/gpu/shaders.js`: `buoy_sample` gains `shMomX`/`shMomY` workgroup arrays, accumulates
  `v.r*m.a` / `v.g*m.a` per cell, reduces them in the same stride loop and writes
  `buoySample[6]`, `buoySample[7]`; the zero-rect branch writes 8 zeros; `sampleCpu`
  accumulates the same sums in the same addresses. one kernel, one buffer, one copy — no new
  channel, no new pass, no extra map.
- `src/gpu/solver.js`: buoy slot grows to 8 floats (32 B); the readback buffer stays 5120 B
  (the buoy slot was already a 256 B slot); `buoyFrame` is tracked at encode and handed to
  `ingest`, mirroring `probeFrame`.
- `src/gpu/fields.js`: the pre-`SAMPLE_LEN`-load fallback constant follows (6 → 8).
- `src/core/save.js`: layout unchanged (`BUOY_SAMPLE_PAD` was already 8 floats; the pad
  becomes the contract, `VERSION` stays 1); on restore, `restoreTables` calls
  `buoy.syncDerived()` so the first post-load framed sample measures real change.
- `src/app/hud.js`: the buoy line gains `mom=(x,y)` and `F=(fx,fy)` in sim units
  (dye-mass·cell/s and dye-mass·cell/s²). no overlay, params slot, config key or view change.
- `README.md`: the dam-float sentence now says the HUD also reports footprint momentum and
  dP/dt, applying nothing to the flow.

## decisions and caveats

- dP/dt is the momentum rate of the fluid inside the block — it includes gravity and the
  boundary flux terms; the footprint pressure integral is not computed and the number is not
  a drag coefficient. it is a scale for the force a displacing hull would feel, nothing more.
- the derivative state is runtime state, never capture state: `syncDerived()` re-anchors it
  on restore instead of serializing `prevFrame`/`prevMom`.
- no two-way coupling (the body still only reads), no second moments, no hull calibration,
  no new pass or channel — all out of scope, deliberately.
- the readback staleness rule now drops the whole snapshot on a generation mismatch, which
  also covers phase and probe legs that previously compared stale captures. a skipped channel
  is simply not ingested that frame; cadences are "at most every N frames".
- device timing is not measured here: HUD `queue ms` with buoy + probe + phase listener
  active (`python3 run_index.py`, then re-read the HUD) is the open row — same row as 0.7.2.
  on-driver coverage of the readback path exists separately: `experiments/api-test.html`
  (run button) reports ALL CHECKS PASSED — 8/8, `texCreated=588 texAlive=0`,
  `bufCreated=380 bufAlive=0`, `validationErrors=0`, `heapDelta=0.0 KB`, engine 100-step
  replay byte-identical (349344 B) (2026-11-09).
