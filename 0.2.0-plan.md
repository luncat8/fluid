# 0.2.0 — milestone 1a: flow

status: planned
depends on: 0.1.0, 0.0.0 section 5.3 / 5.4 / 5.6
cpu reference side: 0.1.1 t8
milestone: draft.txt milestone 1 (the flow half; the color half is 0.3.0)

## 1. goal

a stable incompressible velocity field with gravity, mouse stirring, static obstacles
and solid cells, projected with a variable density poisson solve, plus the debug views
that make the flow inspectable: velocity, pressure, divergence residual. water falls,
piles up, sloshes and swirls; nothing explodes; the divergence residual stays small.

## 2. scope

in: forces, advect_vel, poisson_rhs, project_iter (jacobi), apply_grad, freeze_solid,
boundary, the substepping rule, obstacle painting, mouse interaction, view modes 2-5.

out: conserved color/mass/energy transport (0.3.0), fct (0.3.1), thermal (0.4.0),
phase and gas expansion (0.5.0, so S is present in the rhs but stays zero here),
multigrid (0.6.0).

## 3. design

### 3.1 fields used

	vel rg32float x2, press r32float x2, divsrc r32float x1, mass rgba32float x2
	(mass.a = m is read for rho, mass.rgb stays untouched in this plan), flags x2

rho = mass.a with a floor of rho_vac. rho_f = harmonic mean of the two face neighbours.

### 3.2 forces

	vel += dt * ( g_vec * (rho_ref - rho)/rho_ref  -  g_vec * beta * (T - T_ref) )
T is zero everywhere until 0.4.0, so only the mass term acts here. plus:
	mouse: for cells within radius of the pointer, vel += dt * pointerVelocity * strength
	       with a smooth falloff (1 - r/R)^2, computed from the preallocated input state
	emitters: slot based, momentum kind only in this plan

gravity is applied at cell centres and distributed to the two adjacent faces (half to
each), which is the standard mac way and avoids a half cell phase error.

### 3.3 advect_vel (semi-lagrangian)

for each face, backtrace from the face position by dt * velocity interpolated at that
face, then bilinearly sample the face lattice of the same component. the transverse
component is averaged from the four neighbouring faces of the other lattice.
clamped backtrace position to the interior so ghosts are never sampled as data.
written to the ping pong slot.

### 3.4 poisson_rhs

	b_c = ( u(i+1,j) - u(i,j) + v(i,j+1) - v(i,j) ) / dt - S(i,j)
	b_c = 0 in static solid and frozen solid cells (they are excluded from the solve)
S is read from sfield, which is zero in this plan (it becomes live in 0.5.0).

### 3.5 project_iter (red-black gauss-seidel)

	p_c = ( sum_f w_f * p_nb - b_c ) / sum_f w_f ,  w_f = 1/rho_f for unblocked faces
one color sweep at a time (red dispatch then black dispatch on gpu, ping pong per
color; both colors in place on cpu). K sweeps from params (default 60), hotkey
adjustable so the residual/quality tradeoff can be felt live.

jacobi was measured unusable on the closed box: the checkerboard mode is an exact
eigenvalue -1 of the jacobi iteration there, it oscillates forever at any K (see
findings 2026-10-18). red-black kills it; sor over-relaxation diverges on the
singular all-neumann system (omega stays 1 until multigrid in 0.6.0).

convergence metric: max |div u| after the projection goes into the stats reduction
and the hud, so K can be judged live instead of guessed.

### 3.6 apply_grad

	for each face between L and R:  u -= dt * (p_R - p_L) / rho_f
blocked faces are skipped (their velocity stays 0).

### 3.7 freeze_solid and boundary

	freeze_solid: any face with a static solid or frozen solid neighbour gets u = 0.
	frozen solid is decided by flags.g == solid, which is only ever set by the user
	painter in this plan (phase change arrives in 0.5.0).
	boundary: ghost ring values set per boundary mode
		closed (default): normal velocity 0 on the domain faces, tangential free slip,
			pressure neumann (face dropped from the solve)
		no slip: tangential velocity mirrored with sign flip at the wall
		open edge (per edge flag): p = 0 dirichlet, normal velocity unconstrained,
			mass leaving the domain is charged to the ledger as boundary loss (0.3.0)

### 3.8 obstacle and solid painting

scenario string map (from 0.1.0 t13) plus interactive painting:
	keys 1-3 select paint mode (wall, solid, erase), drag paints into flags.r / flags.g
	painting writes a staging Uint8Array and one queue.writeTexture, never per cell
	painted geometry is static during a step (applied between steps) so no resync needed

### 3.9 substepping and cfl rule

	maxVel from the stats reduction (or a strided estimate every frame, cheap)
	substeps = clamp( ceil(maxVel * dt / cfl_target), 1, substep_max )   cfl_target 0.8
	the per substep dt is dt/substeps, the projection iteration count is unchanged
	(this keeps cost predictable; measured in stability.js)
	velocity hard clamp as a safety net at v_max = 8 cells/dt, logged when it triggers
	a hard clamp is a bug detector, not a physics feature: the counter goes in the hud.

### 3.10 view modes

	0 color (dye, from 0.3.0; here it shows m as greyscale so the field is visible)
	1 temperature (flat until 0.4.0)
	2 pressure (signed colormap, range auto-fit from stats min/max)
	3 velocity (magnitude + direction hue)
	4 divergence residual |div u| after projection (log scaled)
	5 phase/flags overlay (static wall, solid, vacuum) with color underneath
overlay (5) is drawn on top of any other mode when the overlay flag is on, which is
the pattern milestone 3 asks for ("overlay for solid").

## 5. acceptance

- a1 dam break: the heavy block collapses, spreads and settles; no explosion, no
	NaN, no visible checkerboard in the pressure view.
- a2 max |div u| after projection below 1e-3 (lattice units) in the interior with
	K=40 at N=256, shown in the hud; below 1e-2 at N=512 with the same K, or K is
	raised and the new default recorded.
- a3 a static box of uniform rho_liq with zero velocity stays exactly still for 1000
	steps (max |vel| below 1e-6): this catches spurious boundary currents.
- a4 velocity clamp counter stays 0 in all scenarios at the chosen defaults.
- a5 60 fps at N=256 and >= 30 fps at N=512 with K=40 on the dev machine; frame ms
	and per pass timings (timestamp queries if available, otherwise pass grouping) in
	the hud.
- a6 mouse stirring produces persistent vortices that decay slowly, not instantly
	(viscosity default 0 means decay comes only from numerical diffusion).
- a7 gpu parity with the cpu reference below 2e-6 relative on all fields for 100 steps
	from the same initial state and dt.
- a8 painted walls and solids hold: no flow through a one cell thick wall.

## 6. risks and pitfalls

- harmonic vs arithmetic face density: arithmetic mean produces spurious velocities at
	large density ratios. harmonic is the default; if it looks too stiff, measure both
	in projection.js before changing anything.
- staggered sampling bugs in advect_vel (half cell offsets) show up as a drifting
	pattern. the parity test against the cpu reference catches this in one run.
- jacobi with a huge density ratio (rho_liq/rho_vac = 1000) converges slowly. if the
	residual metric says so, options in order: raise K, raise rho_vac, red-black, then
	multigrid (0.6.0). do not silently accept a bad solve.
- open edge + p = 0 dirichlet and mass leaving: the ledger must count it, otherwise
	0.3.0 conservation numbers look broken.
- applying gravity before the projection is correct (the projection removes the
	uniform part); applying it after adds energy every step.
- ghost ring cells must never be advected into or out of: compute_flux zeroes those
	faces in 0.3.0, and boundary must run before compute_flux.
