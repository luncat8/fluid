## 1. goal

turn the demo page into something a game can call: a small, documented, allocation free
api around the solver, with emitters, colliders (including moving ones), point queries for
gameplay logic, deterministic fixed timestep integration, save/load, and a backend neutral
shape so the deferred lattice boltzmann experiment (0.9.0) can be dropped in without
touching a game.

## 2. scope

in: Fluid api surface, backend interface, emitter/collider objects with preallocated
internals, point sampling, save/load, determinism and seeding, a game loop integration
helper, examples/demo.html playground, README api docs.

out: audio, particles, sprites, level editors, network sync, 3d.

## 3. api

classic script tags, one global Fluid. no classes where a plain object and functions do,
no promises in the frame path, no allocation in the frame path.

	create(canvas, cfg) -> sim            cfg optional, defaults from src/core/config.js
	sim.destroy()
	sim.resize(w, h) / sim.setGrid(N)
	sim.step(dt)                          one fixed sim step, substeps inside per 0.2.0
	sim.update(dtReal)                    accumulator + step + render, for game loops
	sim.render()
	sim.reset(scenario)
	sim.paused / sim.singleStep()

	sim.params                            live tunable table (the same object the uniform
	                                      buffer is filled from; mutate in place)
	sim.setTunable(name, value)
	sim.stats(out)                        fills a preallocated out object: totals, drift,
	                                      mins, phase histogram, frame ms, residual
	probes (the sample contract):
	sim.addProbe(x, y) -> id              fixed table, max 32 points, preallocated at
	                                      create; no object per probe per frame
	sim.moveProbe(id, x, y)
	sim.removeProbe(id)
	sim.sample(id, out)                   fills out with m, dye rgb, T, phase, u, v, p for
	                                      the probe's last completed sample. one small
	                                      kernel reads the whole table and the result is
	                                      copied back on the buoy cadence (every
	                                      probeEvery frames, default 4), so the age is
	                                      bounded and known. the stats/buoy generation
	                                      guard drops a readback that lands after reset or
	                                      resize.
	sim.setViewMode(mode) / sim.setOverlay(flag)

	the probe table is the pattern the diagnostic body already proved in 1.0.0: one
	workgroup, a few floats, a small readback, a generation guard. generalize that
	kernel instead of mirroring whole fields. a whole-field mirror at N=512 is 1 MB per
	readback and is still stale by stats_every. an immediate synchronous sample is not
	offered: mapAsync cannot complete without a queue stall. callers read the last
	completed sample and accept its documented age; a game that needs lower latency
	lowers probeEvery and pays for the extra copy. the probe block shares the stats/buoy
	readback path (0.6.0 4.6) instead of adding a third in-flight mapAsync.

	view mode has one writer in the app: the DOM row (gui.2) calls its setMode, which
	updates cfg.viewMode and marks the view dirty. sim.setViewMode must be that same
	writer or delegate to it; bindKeys and game code call it and never assign
	cfg.viewMode directly, so click, hover, keys and external calls cannot disagree.

	emitters:
	sim.addEmitter({kind, x, y, radius, value, dye}) -> id     (object copied into a
	                                      preallocated slot at add time, never per frame)
	sim.moveEmitter(id, x, y)
	sim.setEmitter(id, patch)
	sim.removeEmitter(id)
	kinds: dye, heat, cold, momentum, drain, freeze (a cold sink that forces phi_l down)

	colliders:
	sim.setObstacles(maskArray, w, h)     static geometry, one writeTexture
	sim.paintObstacle(x, y, radius, kind) kind: wall, solid, erase
	sim.addCollider({x, y, w, h or radius, vx, vy}) -> id      moving: each step the mask
	                                      delta is computed on the gpu and the collider
	                                      velocity is imprinted on the fluid at newly
	                                      occupied faces (this is what makes a game object
	                                      push water instead of teleporting through it)
	sim.moveCollider(id, x, y, vx, vy)
	sim.removeCollider(id)

	input:
	sim.attachInput(element) / sim.detachInput()   pointer drag = momentum + selected emitter
	sim.bindKeys(element)

	save/load:
	sim.serialize(outArrayBuffer) -> bytesWritten   all conserved fields + params + flags,
	                                      plus a header with magic, version, N, frame,
	                                      time and the step policy (substepsAuto,
	                                      substepsFixed, substepMax, frameDt). ns changes
	                                      the trajectory, so a replay that restores only
	                                      the fields diverges.
	sim.deserialize(buffer)
	deterministic: same buffer + same params + same step policy + same device -> same
	result (no atomics, fixed iteration counts, fixed summation order; see 0.0.0
	section 10). a mismatched N, version or policy is refused with a clear message.

	events (optional, off by default, for game sfx and logic):
	sim.onPhaseChange(callback)           throttled, batched, called outside the frame loop
	                                      from the stats readback, never during submit

    src/api/engine.js        Fluid.engine.create(canvas, options) -> promise<sim>
    src/core/probes.js       probe table, layout, cpu sampler (the kernel's oracle)
    src/core/emitters.js     32-slot preallocated emitter table + Enthalpy/Upload layout
    src/core/colliders.js    32-slot preallocated collider table + static mask/disc helpers
    src/core/save.js         versioned binary snapshot packer/unpacker & 256-aligned staging
    src/core/stats.js        conservation ledger + batched phase-transition event scanner
    src/gpu/shaders.js       probeSample (4x8), applyEmitters (8x8), emitterTally (1x64),
                             paintSolid (8x8), colliderMask (8x8), copyFlags (8x8),
                             colliderVel (8x8), phaseChangeRow (N/8x8), phaseChangeCompact (1x1)
    src/core/pacing.js       the one-frame-in-flight gate (moved from src/app/)
    experiments/api-test.js  20-cycle create/step/serialize/deserialize/destroy + 100-step replay
    experiments/api-test.html browser WebGPU runner for t12 lifecycle & replay checks

decisions that differ from the sketch above, all of them simplifying:

    update(dtReal)          one fixed step per call, debt capped at two frame periods,
                            one submission in flight. catching up three steps in one
                            callback would just queue work already known to be late.
    step(dt)                dt becomes the fixed frame dt (cfg.frameDt); the substep
                            policy reads it, so a caller cannot desync policy and step.
    probes                  32 stable slots, not 32 objects: ids survive remove of
                            another probe. the kernel returns m, dr/dg/db, E, u, v, p;
                            T and phase are derived on the cpu by phaseInto, so the
                            caloric EOS keeps one definition.
    emitters                32 stable slots (528 floats: 16-float header + 32x16-float
                            slots) with zero hot-path allocation. momentum runs inside
                            forces; dye/drain/heat/cold/freeze run in applyEmitters
                            after conduction (zero extra dispatches when no scalar
                            emitter is active). thermal deltas accumulate directly in
                            therm.b/therm.a; dye/drain deltas accumulate in a 20-float
                            GPU Kahan emitterLedger copied out in statsReduceB and
                            paired via a pendingEmitNet snapshot so async stats
                            readbacks never race interleaved paintDye patches.
    colliders & obstacles   flags.r bit-packs static walls (bit 1u), active moving
                            colliders (bit 2u), and newlyOccupied delta (bit 4u, cleared
                            each substep by phaseEos) while preserving legacy 255 walls.
                            32 stable collider slots (528 floats) support circle and rect
                            shapes with zero hot-path allocation. idle or stationary
                            colliders add zero per-frame GPU dispatches after stamping
                            their mask; moving colliders run colliderMask+copyFlags once
                            per moved frame and colliderVel before projection without
                            creating or deleting mass, and feed live peakSpeed into
                            step()'s auto-CFL substep policy.
    sample(id,out)          false until the first readback and after reset/resize;
                            out.age is measured in frames, out.valid is explicit.
    setViewMode             delegates to bindViewMode(fn) when the page owns the
                            control, otherwise writes cfg.viewMode itself.
    setGrid(n)              clamps to [64, 1024]; the repaint resize submits is marked
                            in the pacing gate so the next update waits for it, and
                            live probes + emitters are re-uploaded into the new pool.
    attachInput             installs pointer + keys and returns the input handle;
                            detachInput/destroy remove every listener.
    bindKeys(element)       installs a keyboard-only binding on that target (defaulting
                            omitted element to window); detachKeys removes it without
                            touching pointer input, rebinding replaces only the previous
                            key owner, and r/n/[/] route through engine reset/setGrid.
    create(canvas,opts)     opts.cfg is copied, opts.device/context/format let the
                            node harness create the same engine over the mock device.
    serialize / deserialize async serialize(out) captures all 8 live GPU textures plus
                            emitterLedger in a single command submission into a transient
                            256-aligned staging buffer (destroyed in finally {}) and
                            packs a versioned little-endian ArrayBuffer (256 B header,
                            52 f64 CFG_KEYS snapshotted before mapAsync, 96-element f64
                            CPU state, 24-key ledger, probe/emitter/collider/buoy tables,
                            and 9 tight field blocks). synchronous deserialize(buf)
                            validates magic, version, N, scenario, and all 52 CFG_KEYS
                            (naming the offending key and value on mismatch) and restores
                            all ping-pong texture slots, tables, and generation guards.
    onPhaseChange(cb)       deterministic two-pass GPU scan (phaseChangeRow +
                            phaseChangeCompact, zero atomics, zero workgroup barriers)
                            compares flags.g against pool.phasePrev, sums the 6x6
                            transition matrix, and compacts up to 64 cell records into
                            560 floats. off by default (0 dispatches, 0 copies); fires
                            from pollReadback() outside submit only when total > 0.

## 4. backend interface

Fluid.gpu.solver and (later) Fluid.gpu.lbm implement the same shape:

	init(device, cfg), allocate(N), step(params), render(view), readback(field),
	stats(), destroy(), and the field names of 0.0.0 section 7 where they exist

cfg.backend selects it. an lbm backend does not have press or divsrc, and its S/expansion
is native, so the interface is expressed in terms of what the app needs (step, view modes,
sample, serialize), never in terms of a pass graph. this is the only structural work in
this plan that exists for 0.9.0; everything else is api.

## 5. integration helper

	fixed timestep: update(dtReal) clamps dtReal to 0.1 s, accumulates, steps in fixed dt
	 chunks (default 1/60) with a max of 3 catch up steps, then renders once.
	the step count comes from `config.substepCount(cfg, maxVel)`, the same function the
	demo, the CPU reference and the mock use. do not re-derive the policy in the api:
	that duplication is how "off means one step" survived in a test once already.
	interpolation: none for the field (a fluid does not need it), but the render can use the
	 previous display texture for a crossfade if a game wants it; documented as optional.
	visibility: on document visibilitychange, pause the accumulator so a background tab does
	 not build up a debt and explode on return.
	teardown: destroy() releases every texture, buffer, pipeline and bind group, and drops
	 the device reference; verified by a create/destroy loop of 20 iterations with no growth
	 in device memory or bind group count.

## 8. acceptance

- a1 examples/demo.html runs at 60 fps at N=256 with a moving collider, emitters, overlay
	and meters active, opened from file://.
- a2 a moving collider pushes fluid: dragging it through water creates a wake and raises the
	water level on the far side; teleporting it does not create mass (m drift_rel stays 0).
- a3 serialize -> reset -> deserialize reproduces the field exactly (byte identical
	conserved fields), and continuing the sim from both states gives identical stats for 100
	steps with the same step policy; a different policy is rejected or reported, not
	silently replayed.
- a4 api-test.html: 20 create/destroy cycles, no growth in textures, buffers, bind groups
	or js heap beyond a fixed slack; zero uncaptured webgpu errors.
- a5 sample() returns the right phase for a point inside ice, water, steam and vacuum in the
	water cycle scenario (checked against the phase view).
- a6 no allocation in update()/step()/render() on the hot path, verified with a temporary
	allocation counter and a heap snapshot diff over 1000 frames. As built: 200 engine
	frames (`update`/`render`/`stats`/`sample`) and 100 CPU reference steps allocate `0`
	typed arrays or ArrayBuffers inside `src/`; the counter is a positive-control assertion
	(harness allocations must still be visible), so a broken detector cannot pass. Object
	literals are not covered - `subarray`/`slice` and `{}` do not run a constructor.
- a7 README api section is enough to write the demo from scratch without reading src.

## 9. risks and pitfalls

- api creep: every method must be justified by the demo or a test. anything else stays out.
- moving colliders are the hardest part: the mask delta has to be computed against the
	previous step's mask, and imprinting velocity on newly occupied faces must not create mass
	(it changes velocity only, never m).
- save/load with different grid sizes: store N in the header and refuse a mismatched load
	with a clear message (no legacy resampling — AGENTS.md: no legacy support).
- serialize must not stringify (slow, allocates); write into a caller provided ArrayBuffer
	with a documented layout.
- events fired during submit would stall the gpu; batch them from the readback path only.
- probes are stale by design: document the age and the probeEvery knob, do not hide it.
	do not add a synchronous sample path; a queue stall is worse than a 4-frame-old value.
