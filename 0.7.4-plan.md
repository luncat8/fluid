# 0.7.4 — make a non-finite field loud (stats `nonfinite` count + HUD banner)

status: implemented, validated headlessly (quick suite + full); device row open
depends on: 0.6.0 t1 (gpu stats reduction), 0.7.2 (one readback, one stats slot), 0.7.3 (stats ingest)
source: the 0.7.3 device capture (`archive/0.7.3-worklog.md` "device pass"), where the demo page
reported a healthy field while the probes read `—`

## 1. what the capture showed

three snapshots, taken ~20 s apart on a real driver, N=256 `dam` with the six-emitter rig:

	probe 0   205,191  m 0.302  T 293.0 K  liquid   u,v,p = —      <- non-finite velocity
	probe 1   104,25   m 0.039  T 373.0 K  boiling  u,v,p = —      <- non-finite velocity
	Conservation   mass +8.63e-6   energy -3.48e-6
	cells liq=5686 gas=1429
	maxVel=0   maxDiv=0     <- reported as a perfectly calm field

`—` is `fmt()`'s non-finite branch (`examples/demo.js`, `src/app/hud.js`): those probes hold a
finite mass and a finite temperature but a **NaN** `u`, `v` or `p`. The meters above them came
from the same readback and said `maxVel=0 maxDiv=0`.

## 2. why the meters said nothing

`statsReduceA` seeds `maxVel`, `maxDiv`, `pMin`, `pMax` and folds them with WGSL `max()`/`min()`.
WGSL `max(x, NaN)` and `min(x, NaN)` return `x` — the non-NaN operand — so a NaN anywhere in the
velocity or pressure field is **dropped by the reduction** and every derived meter reads clean:

- `maxVel=0`, `maxDiv=0`, `p[0..0]`: NaN never wins a max.
- `maxM` looks small: the cell that swallowed the mass is NaN, not large.
- `poisson res/rhs` look *better* than healthy (16.7 -> 0.19, 0.0080 -> 0.0011) because the NaN
  cells are skipped by `poissonOpen`'s early return.
- the `kinetic` energy term is `0.5*m*(uc^2+vc^2)` = NaN, so it must be dropped by the kahan sum
  as well — and indeed `E: total=113015120 exp=113015120.9 drift=-8.2e-9 [ok]` was reported while
  the field was already dead. a NaN in the sum should have poisoned it.

the cpu oracle has the same hole for a different reason — `stats.js` compares with `<`/`>`, and
every comparison against NaN is false, so a NaN cell updates no extremum and no counter.

so the failure is silent on **both** paths, and it cost three 0.7.x rounds: 0.7.1 was recorded as
"then broken", 0.7.3 reproduced it, and neither capture can say which frame died or which field
died first, because nothing counted.

## 3. fix, part one: count it (the part a device can answer)

Five counters in the five free floats of the existing stats slot — no new pass, no new buffer,
no new copy, no layout move. The stats slot is 46 floats inside a 256-byte (64-float) aligned
slot, so `STATS_LEN` 46 -> 51 still fits and the one-map rule is untouched.

	slot  name              field it counts
	46    IDX_NONFINITE     any of the below at that cell (the headline number)
	47    IDX_NF_MASS       m, dr, dg, db
	48    IDX_NF_THERM      E, T
	49    IDX_NF_VEL        u, v
	50    IDX_NF_PRESS      p

- `src/core/stats.js`: the five constants and `STATS_LEN=51`. `totalsFromFields` counts `m/dr/dg/db`
  into `cntNfMass` and `E` into `cntNfTherm`; `motionTotals` counts `u,v` into `cntNfVel` and `p`
  into `cntNfPress`. the test is `Number.isFinite`, because this is precisely the check that
  `<`/`>` cannot express — every comparison against NaN is false, which is why the cpu oracle
  also reported a calm field. `packStatsArray` writes all five.
- `src/gpu/shaders.js`: `statsReduceA` adds the same five channels as 0.0/1.0 flags per cell
  (`x != x` for f32 non-finite), reduced with `+` in both the workgroup stride loop and
  `statsReduceB`, so they survive the NaN-blind `max`/`min` used for the other extrema.
- `src/gpu/solver.js`: `ingestStats` reads slots 46..50 into `statsCache.cntNonFinite` and
  `statsCache.nonFinite={mass,therm,vel,press}`; `getStats()` exposes both.
- `src/gpu/solver.js`: `ingestStats` reads slot 46 into `statsCache.cntNonFinite`;
  `getStats()` exposes it.
- `src/app/hud.js`: `healthLine` leads with `NON-FINITE FIELD: N cells (m=.. T=.. u,v=.. p=..)`
  when the count is non-zero, and `buildSnapshot` prints the same on the min/max line so a pasted
  report carries it with the health line stripped. `hud.fmt()` already returns non-finite values
  unchanged, so a NaN stays visible instead of becoming a plausible number.
- `examples/demo.js`: the conservation meter gains `nonFinite=N` next to `neg=` / `over=`.

Nothing else changes: no physics, no numerics, no layout move, no threshold moved.

## 4. fix, part two: say when (the diagnostic the next device run needs)

A count says "it is dead now". The captures show it died *mid-transient* (frame#691 healthy ->
frame#781 `maxDiv 28.6`, `over 457` -> dead, `maxVel=0`), so the first question is always "which
frame". A small latch beside `statsCache` in `src/gpu/solver.js` records the first stats frame
whose `nonFinite` count went 0 -> non-zero, exposes it as `stats().firstNonFiniteFrame` (-1 when
clean), and is cleared by `reset()` / `resize()`. It is runtime state and is not serialized, the
same rule the buoy `dP/dt` baseline follows.

## 5. what this does not do

- it does not stop the divergence. the root cause is not identified here: the cpu oracle
  (`Fluid.core.solver`) is clean on every path that was reachable headlessly — the emitter rig,
  the collider drag at 480 u/s, freeze/drain, `cycle`, 900 frames at N=160 — so whatever breaks
  is in wgsl or in the driver, and no headless harness in this repo executes wgsl. with a
  `nonFinite` count, the next device capture names the frame and the field, which is the input
  the search needs; without it the captures keep arriving as three snapshots of a corpse.
- it does not change `OVER_EPS`/`NEG_EPS` behaviour, the `[ok]` drift verdicts, or any threshold.
  a NaN in a totality is now *counted*, not reclassified: `driftRel` still returns NaN and
  `formatDrift` still says `bad` for it.

## 6. validation

- `python3 run_tests.py` and `--full` (see the worklog for the recorded numbers).
- new conformance checks (`experiments/conformance.js`): `totalsFromFields` counts a NaN mass cell
  and a NaN energy cell; `motionTotals` counts a NaN velocity and a NaN pressure; a clean field
  reports 0 on all five; `packStatsArray` carries the five counts.
- new mock checks (`experiments/gpu-mock.js`): `statsReduceA`'s five non-finite channels exist and
  are summed (not maxed) in both reduce stages; the WGSL lint sees `!=` tests for the four mass
  slots, `E`/`T`, both velocity components and pressure; `ingestStats` lands canned slot-46..50
  values on `stats().cntNonFinite` and its breakdown; the first-seen latch holds the first frame
  and clears on reset.
- new hud checks (`experiments/hud.js`): `healthLine` leads with the banner at 1 cell and stays
  silent at 0; `buildSnapshot` prints `nonFinite=` and `firstNonFiniteFrame`.
