# 0.7.3 — footprint momentum diagnostic (+ one readback staleness drop)

status: implemented, validated (quick suite + full 21/21 headless; device HUD `queue ms` measured 2026-11-09 — see archive/0.7.3-worklog.md device pass)
depends on: 1.0.0 (buoy body + sample contract), 0.7.0 t5/t6/t9 (readback slot table), 0.7.2 (one map per frame)
source: archive/1.0.0-worklog.md "next" ("a second sample slot for the momentum of the fluid
inside the footprint ... the force a real obstacle would feel"), reaffirmed in
archive/0.7.2-readback-worklog.md "next" ("the same slot mechanism is the natural home").

## 1. goal

the buoy body reports — never applies — the fluid momentum inside its footprint: two
mass-weighted sums, the mass-weighted mean velocity, and dP/dt between consecutive field
samples. that is the quantity a displacing hull would have to push against, read off the
same pass that already samples the block. it is a diagnostic for the dam float and for the
moving-collider momentum work in 0.7.0, not a calibrated force model.

second, small: a staleness fix found while reviewing 0.7.2. a readback that landed after a
reset or a load could still be ingested, because the stats and probe legs compared two
values captured before the reset instead of against the current generation.

## 2. why the sample contract, not a new channel

the `buoy_sample` kernel already walks the footprint once, accumulating six raw sums with
a workgroup reduction. momentum is two more sums (`Σ m·u`, `Σ m·v`) in the same pass: one
kernel, one storage buffer, one copy, one map — no new channel, no new pass, no extra map.
the alternative — a separate two-float slot — would double the buoy copies and duplicate the
generation plumbing to carry two floats.

the capture format already had exactly this headroom: `BUOY_SAMPLE_PAD` is 8 floats while the
contract used 6. the pad becomes the contract; the layout does not move and VERSION stays 1.

## 3. changes

### 3.1 sample contract (`src/core/buoy.js`)

`SAMPLE_LEN` 6 → 8: `S_MOMX=6`, `S_MOMY=7`, raw unnormalised sums like every other slot.
`sampleCpu` (the cpu twin of the kernel) accumulates `mass·vel` per cell. `ingest(fresh,
frame)` gains an optional frame stamp (frame numbers, same convention as `pendingFrame` /
`probeFrame`); without one the derivative is not updated. state gains `momX`, `momY` (the
raw sums), `uMass`, `vMass` (mass-weighted mean velocity, 0 when the footprint carries no
mass — distinct from the count-weighted `ux`,`uy` near the free surface) and `forceX`,
`forceY`.

the derivative is cpu-side and lives in the closure (`prevMomX`, `prevMomY`, `prevFrame`),
not in the capture: force = Δ(Σ m·u) / ((f₂−f₁)·cfg.frameDt) between consecutive framed
ingests. the first framed ingest after a reset or a baseline reports force 0 rather than a
spike against zeros. `syncDerived()` recomputes `momX/momY/uMass/vMass` from the current
sample, re-bases the closure and zeroes force — the save/restore path calls it so the first
post-load sample measures change from the restore point, not from construction.

### 3.2 kernel (`src/gpu/shaders.js`)

`buoy_sample` gains `shMomX`/`shMomY` workgroup arrays, accumulates `v.r*m.a` / `v.g*m.a`,
reduces them in the same stride loop and writes `buoySample[6]`, `buoySample[7]`. the
zero-rect branch writes 8 zeros. workgroup shared memory stays 2 KB.

### 3.3 readback and the staleness drop (`src/gpu/solver.js`)

the buoy slot grows to 8 floats (32 B); the total readback stays 5120 B (the buoy slot was
already 256 B). the copy length follows `buoyZero` as before. `buoyFrame` is tracked at
encode and passed to `ingest`, mirroring `probeFrame`.

pollMap keeps one shared staleness rule: after `mapAsync` resolves, compare the generation
captured at poll start against the *current* `statsGeneration`. a reset, a resize or a load
bumps it, so the entire snapshot belongs to the previous field and is dropped as one — no
channel is ingested. this replaces the per-channel generation compares, which compared two
pre-reset values on the stats and probe legs (both were ineffective; buoy and phase were
re-based and worked). `pendingGeneration`, `buoyGeneration`, `probeGeneration`,
`phaseGeneration` collapse into that one check; `buoyFrame`/`probeFrame`/`phaseFrame` stay,
as they carry ingest stamps.

### 3.4 persistence (`src/core/save.js`)

layout unchanged (`BUOY_SAMPLE_PAD` already 8); `buoy.sample` now stores 8 meaningful
floats. on restore, `restoreTables` recomputes the derived momentum fields from the restored
sample and calls `buoy.syncDerived()` — no force spike on the first frame after a load, and
the hud never shows construction-time momentum for a loaded field.

### 3.5 display (`src/app/hud.js`)

the buoy line gains `mom=(x,y)` and `F=(fx,fy)` in sim units (dye-mass·cell/s and
dye-mass·cell/s²). no overlay, params slot, config key or view change.

## 4. validation

- `experiments/conformance.js`: mass-weighted sums and mean vs the count-weighted mean on a
  synthetic field; dP/dt exact on a two-frame synthetic pair; force 0 on the first framed
  sample after `reset()` and after `syncDerived()`; existing buoy checks unchanged and still
  green; field bit-identical with the body on.
- `experiments/gpu-mock.js`: buoy slot len 8 at a 256-aligned offset; 32-byte buoy copies;
  slot table still sums to 5120 B; kernel lint (8-float zero fill, two extra reductions);
  canned pattern carries 8 floats and reaches `state.momX/momY/uMass`; new check: `reset()`
  while a map is in flight drops the whole readback (`getStats().statsFrame` stays 0).
- `experiments/engine.js`: canned buoy pattern extended to 8 floats; the one-view-per-map
  audit is unchanged.
- `python3 run_tests.py`; `python3 run_tests.py --full` before close.

## 5. non-goals

no hull-force calibration: dP/dt is the momentum rate of the fluid inside the block, which
includes gravity and the boundary flux terms — the pressure integral over the footprint is not
computed, and the number is not a drag coefficient. no momentum-flux second moments, no
two-way coupling (the body still only reads), no rotation, no capture of the derivative
state (`syncDerived()` re-bases on restore instead), no new readback channel or kernel, no
device-timing claim — the open row remains the browser HUD `queue ms` with buoy + probe +
phase listener active (`python3 run_index.py`), which only a device can answer.
