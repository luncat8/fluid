# 0.1.0 — page, webgpu harness, field pool, dispatch graph

status: planned
depends on: 0.0.0
milestone: infrastructure (nothing from draft.txt is visible yet, but everything
after this is assembly work)

## 1. goal

a page that opens from file://, gets a webgpu device, allocates the whole field set
of 0.0.0 section 7, runs a compute pass graph with ping pong, draws the result
through a fullscreen triangle, and shows a hud with frame time plus conservation
meters. prove the plumbing with the simplest possible sim content: a dye pattern
that diffuses (one exchange kernel) so ping pong, ghost ring, params uniform, stats
reduction, readback and display all get exercised end to end.

## 2. scope

in: device init and error surfacing, texture/buffer pool, bind groups built at setup,
params uniform layout, one compute kernel family (exchange + copy), two level stats
reduction, async readback, to_display colormaps for color/temperature, render pass,
hud, input state, fixed dt loop skeleton, resize, capability probe.

out: real physics (0.2.0+), fct limiting (0.3.1), multigrid (0.6.0), public api (0.7.0).

## 3. design

### 3.1 device.js

	requestAdapter({ powerPreference: "high-performance" })
	requestDevice({ requiredFeatures: [], requiredLimits: {} })   core defaults only
	context.configure({ device, format: gpu.getPreferredCanvasFormat(), alphaMode: "opaque" })
	device.lost.then(...) -> on screen panel with the reason
	device.onuncapturederror -> on screen panel with the message (this is the single
	most valuable debug tool in webgpu, never leave it silent)

capability probe, run once, printed to console and to the hud help panel:
	adapter.info (vendor, architecture, description), isSecureContext, location.protocol
	device.limits (the ones we care about), device.features (list what is available)
	the three storage formats we depend on verified by actually creating a 2x2 texture:
	rg32float, rgba32float, rgba8uint, r32float, rgba16float
	navigator.gpu missing or requestAdapter null -> message panel with the exact
	fallback: run python3 -m http.server in the repo root and open http://localhost:8000

first task of the implementation is the probe alone, opened from file:// in the
target browser, and the result written into findings-pitfalls-skills.md. everything
else in this plan is pointless if file:// has no webgpu.

### 3.2 fields.js

field descriptor table (flat data, no per frame objects):

	name, format, bytesPerCell, copies (1 or 2), usage flags, initial value

all textures: TEXTURE_BINDING | STORAGE_BINDING | COPY_SRC | COPY_DST.
COPY_DST for queue.writeTexture at init/scenario load, COPY_SRC for parity readback.

ping pong: a pair is { tex: [t0, t1], cur: 0 }, and swap() flips cur. bind groups are
precreated for both orientations of every pass (a static graph has a static, small
set of bind groups), so the frame loop only picks an index.

obstacles/initial state upload: staging typed arrays allocated once per field,
filled by the scenario, then queue.writeTexture with the padded bytesPerRow
(bytesPerRow must be a multiple of 256 for copyTextureToBuffer, writeTexture has no
such constraint but the readback path does; see 3.6).

### 3.3 params uniform layout

one storage buffer of f32 with a fixed offset table documented in src/core/config.js
and mirrored in wgsl as a struct with the same field order. groups:

	0..15   grid: N, invN, texW, texH, dt, substeps, time, frame
	16..31  forces: gravity_x, gravity_y, rho_ref, beta, T_ref, mouse_x, mouse_y, mouse_strength
	32..47  solver: jacobi_iters, fct_limiter, viscosity, conductivity, S_max, tau_phase
	48..79  eos: c_sol, c_liq, c_gas, L_f, L_v, T_melt, T_boil, rho_liq, rho_gas0, rho_vac, m_eps
	80..95  view: mode, colormap ranges (T_min, T_max, p_min, p_max, v_max), overlay flags
	96..127 emitters/heaters: up to 4 slots of (x, y, radius, kind, value, dye_r, dye_g, dye_b)

written every frame with queue.writeBuffer from one preallocated Float32Array that is
mutated in place. no object literals, no array literals, no string work.

### 3.4 first kernels (plumbing proof)

	exchange_kernel   the clamped pairwise exchange of 0.0.0 section 5.7 applied to
	                mass.rgba with a tiny coefficient -> dye blobs soften, nothing else
	                happens. exercises stencil reads, ping pong, ghost ring, clamp.
	copy_kernel       field -> field, used for reset and for the second ping pong slot
	to_display        view modes 0 (color = dye rgb) and 1 (temperature colormap)
	stats_reduce_a    per workgroup partial sums into stats_part via workgroup memory
	stats_reduce_b    partials -> stats (totals of m, dr, dg, db, E, and min values)

workgroup size 8x8 = 64 for every kernel (safe under the 128 invocation limit of
compatibility mode and good occupancy for stencil kernels). dispatch =
ceil(texW/8) x ceil(texH/8), and every kernel early returns outside the ghost padded
interior region.

### 3.5 frame loop (src/app/main.js)

	accumulator += min(frameDelta, 0.1)     clamp so a tab switch cannot explode
	while (accumulator >= dt) { substep(); accumulator -= dt; }   substeps capped
	render(); hud.maybeUpdate(now);

substep() = one command encoder -> one compute pass with all dispatches -> one render
pass -> queue.submit. zero allocations inside, everything precreated at setup.

### 3.6 stats readback

	copyBufferToBuffer(stats -> stats_read) then mapAsync once, guarded by an
	inFlight flag. consumed on a later frame. never awaited inside the frame loop.
	hud period: stats every stats_every frames (30), text every 200 ms.
	parity readback path (used by experiments/gpu-parity.html): copyTextureToBuffer
	with bytesPerRow padded to a multiple of 256, then unpack row by row.

### 3.7 hud

fixed position div, monospace, three blocks:
	perf: fps, frame ms, submit count, grid, substeps, jacobi iters
	conservation: for each of m, dr, dg, db, E -> total, expected, drift_rel, min value
	state: view mode, paused, selected emitter, key help
drift_rel is colored (green under 1e-6, yellow under 1e-3, red above) so a regression
is visible without reading numbers. text is built with a preallocated array of
strings joined at 5 hz — the one acknowledged allocation site (AGENTS.md: not strict).

### 3.8 keyboard and pointer

	keys: 0-5 view modes, space pause, . single step, r reset, h help, +/- iterations,
	      [ ] grid size, g toggle gravity, s dump stats to console, d dump field to console
	pointer: store x, y, dx, dy, down in a preallocated object, consumed by forces (0.2.0).
	in this plan the pointer only paints dye into mass via writeTexture on drag, which
	is enough to test the meters.

## 6. acceptance

- a1 opens from file:// (or the documented fallback if the probe says file:// is not
	a secure context) with no console errors and no uncaught webgpu validation errors.
- a2 dye blobs visibly soften under the exchange kernel and stay inside the domain
	(ghost ring correct: nothing appears in or leaks through the border).
- a3 hud shows drift_rel for m, dr, dg, db, E and all five stay below 1e-6 while the
	exchange kernel runs (it is conservative by construction; if they do not, the
	reduction or the kernel is wrong and this plan is not done).
- a4 min(m) and min(dye) never negative.
- a5 60 fps at N=256 with the placeholder graph on the dev machine, frame ms shown.
- a6 resize does not leak (texture count stable across 10 resizes) and does not
	allocate in the frame loop (verified by a temporary allocation counter in dev).
- a7 pause, single step, reset and all view mode keys work.
- a8 the capability probe output is recorded in findings-pitfalls-skills.md.

## 7. risks and pitfalls

- file:// may not be a secure context in some browsers -> probe first (t2), fallback
	documented, no silent failure.
- write-only storage textures cannot be read in the same binding: any kernel that
	needs a neighbour value must bind the source texture separately. the ping pong
	design already assumes this.
- rgba32float cannot be read_write in core webgpu; do not "optimize" into in place
	updates. r32float can, and that is the only place where an in place pass is legal.
- ghost ring + early return: a stencil kernel that reads outside the texture returns
	zeros silently in wgsl (out of bounds textureLoad is defined as zero) which hides
	index bugs. clamp explicitly and assert on the cpu reference instead.
- bytesPerRow multiple of 256 on copyTextureToBuffer, not on writeTexture.
- bind group layout must match the pipeline layout exactly; build both from one table.
- hud string building every frame is a real cost; throttle.
- device limits: do not request anything above the defaults, it reduces the set of
	machines that can run the page.
